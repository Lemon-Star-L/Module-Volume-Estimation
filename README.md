## 1. 项目概述

本项目以备件收货模块为统计对象，按日期汇总各模块收货数量，并匹配同日运输业务方量，形成“每日各模块收货数量—每日运输总方量”矩阵，进而估计各备件模块的单位方量（m³/件）。

项目包含三个主要环节：

- **模块数量整理：**
  从月度收货业务数据中提取汽运收货记录，根据SKU与备件模块映射关系，汇总每日各模块收货数量。
- **运输方量整理：**
  从运输业务记录中清理重复及无效数据，按发运日期汇总每日运输方量。
- **矩阵合并与参数求解：**
  按日期将每日运输方量匹配到模块数量矩阵，建立求解模型，估计各模块单位方量。

模型采用以下基本关系：

$$
V_i = \sum_{j=1}^{m} Q_{ij}v_j + \varepsilon_i
$$

其中：

- `V_i`：第 `i` 个样本日的运输总方量，单位为 m³。
- `Q_ij`：第 `i` 个样本日内模块 `j` 的收货数量，单位为件。
- `v_j`：模块 `j` 的单位方量，单位为 m³/件。
- `ε_i`：未被线性模型解释的差异。

该模型假设同一模块的收货数量可以按固定单位方量进行线性叠加。严格方程模式要求方量等式成立；其他模式根据各自的损失函数、约束或预测方法估计参数。

**重要说明：**
模型估计的是当前数据统计范围内的模块平均单位方量，不等同于对每个零件进行实物测量，也不自动代表标准包装尺寸或单件实际占用体积。

`execute.py`。

如需维护模块映射，可按需运行 `model.py`，人工复核后再维护
`data/Resource.xlsx`。

## 3. 主数据预处理（按需）

### 3.1 `model.py`：模块辅助匹配

**输入：** `model/备件模块信息.xlsx`，需要包含
`映射表`、`模块信息_Operate` 两张工作表；另需
`model/direct/日用品字典.csv`、`model/direct/汽车配件字典.csv`。
**输出：** `model/映射表（近似）.xlsx`。

主要字段：

| 数据位置           | 必需字段及约束                                                                             |
|:-------------------|:-------------------------------------------------------------------------------------------|
| `模块信息_Operate` | `备件名称`、`区`、`备件模块`，以及 `件号` / `备件编码` / `零件号` 至少一个；`备件SKU` 可选 |
| `映射表`           | `备件名称`，以及 `模块名称` 或 `备件模块`                                                  |
| `日用品字典.csv`   | `关键词`；可配置 `匹配方式`、`排除词`                                                      |
| `汽车配件字典.csv` | `关键词`、`模块`；其他字段可用于判定说明                                                   |
| `人工修正.csv`     | `件号`、`备件名称`、`确认模块`；文件不存在时自动创建空模板                                 |

当前配置：

- `REPROCESS_UNCLASSIFIED = False`：仅处理源表中模块为 `#N/A` 的记录。
- 设置为 `True`：同时处理空白及”未分类…“记录。
- `MIN_SCORE = 82`：近似匹配分数阈值。
- `MIN_MARGIN = 8`：候选模块分差阈值。
- `SHORTLIST = 100`：近似匹配初筛候选名称数量。

匹配优先考虑人工修正，再结合日用品关键词、既有模块映射、名称规范化与主体相似度、汽车配件字典等规则判定。程序对无法确认的记录输出
`未分类` 或带参考类别的 `未分类（…）`，并提供判定依据与候选项。

输出包含三个工作表：

| 工作表     | 内容                                                                                  |
|:-----------|:--------------------------------------------------------------------------------------|
| `近似`     | 件号、货品名称、区、备件模块；保留本次待处理记录顺序与重复行                          |
| `匹配明细` | 原表行号、SKU、件号、备件名称、原分类、最终模块、匹配来源、复核标记、判定依据及候选项 |
| `处理统计` | 程序版本、字典数量、匹配来源计数及无效映射排除数量                                    |

匹配分数不等同于匹配准确率。辅助归类结果须经业务复核后再作为正式模块使用。脚本不修改源文件，也不自动写入
`data/Resource.xlsx`。

## 4. 模块数量矩阵生成：`pre_execute.py`

### 4.1 输入文件与字段

**业务数据：** `data/execute/` 目录下的月度文件，命名格式为
`YYYY.MM.xlsx`，例如 `2026.07.xlsx`。 **主数据：**
`data/Resource.xlsx`，包含 `备件信息`、`模块信息` 两张工作表。
**输出：** `output/A_temp_result.xlsx`、`output/A_temp_erro.xlsx`。

| 数据位置                     | 必需字段                                   |
|:-----------------------------|:-------------------------------------------|
| 月度业务表                   | `箱号日期`、`发运方式`、`货品编码`、`数量` |
| `Resource.xlsx` → `备件信息` | `SKU`、`备件模块`                          |
| `Resource.xlsx` → `模块信息` | `备件模块`、`自变量`                       |

程序自动扫描符合 `YYYY.MM.xlsx`
格式的文件，按年月顺序处理；同一个月份存在多个同名期间文件时会报错。业务工作簿可包含多个工作表，程序逐表读取。普通
XLSX 与 Strict XLSX 均有兼容读取处理，Strict
格式转换仅发生在临时副本中，不修改源文件。

### 4.2 计算规则

程序根据 `Resource.xlsx` 建立 SKU
到备件模块、备件模块到自变量列的映射。模块自变量按表内顺序依次为
`x1`、`x2`……。

每日形成一行矩阵：

``` text
x1模块数量 | x2模块数量 | ... | xm模块数量 | 日期
```

处理规则：

1.  仅将 `发运方式` 为”汽运”的业务记录纳入正常矩阵。
2.  根据 `货品编码` 匹配 `Resource.xlsx` 中的
    SKU，再确定备件模块及自变量列。
3.  同一日期、同一模块的有效收货数量进行累加。
4.  日期按升序排列，不补充没有业务记录的自然日。
5.  跨文件、跨工作表检查重复业务记录；重复判定忽略
    `箱号日期`，其余字段参与比较。
6.  数量支持数值及文本数字，支持符合三位分组规则的中英文逗号千位分隔格式。
7.  使用十进制数值进行数量累计及核对。

### 4.3 异常处理

| 场景                                   | 处理方式                           |
|:---------------------------------------|:-----------------------------------|
| 非汽运记录                             | 剔除，不纳入模块数量矩阵           |
| 发运方式为空                           | 记录异常并剔除                     |
| 必填字段为空                           | 记录异常并剔除                     |
| SKU未匹配                              | 记录异常，进入人工复核             |
| 一个SKU对应多个模块                    | 记录模块映射异常并剔除             |
| 模块无法匹配自变量或模块对应多个自变量 | 记录模块映射异常并剔除             |
| 跨文件或跨工作表重复记录               | 记录重复原因并剔除                 |
| 日期无法识别或不属于文件月份           | 作为严重数据错误处理               |
| 数量为空或格式非法                     | 记录异常；非法数量属于严重数据错误 |
| Resource结构或模块顺序异常             | 预检查失败，不发布本次新矩阵       |

异常记录保留完整原因。每条剔除记录按优先级归入一个异常类别，但明细中保留全部命中原因。程序核对原始数量、纳入矩阵数量和剔除数量之间的平衡关系。

### 4.4 输出文件

| 文件                                     | 内容                                                                    |
|:-----------------------------------------|:------------------------------------------------------------------------|
| `A_temp_result.xlsx` → `矩阵_去除全零行` | 删除模块数量全部为零的日期                                              |
| `A_temp_result.xlsx` → `矩阵_保留全零行` | 保留全部有效日期，包括模块数量全零的日期                                |
| `A_temp_erro.xlsx`                       | 存在异常记录时生成，包含异常明细、处理统计、数量核对及SKU未匹配复核信息 |

两个矩阵工作表均无表头；前面各列为模块数量，最后一列为日期。`merge.py`
使用 `矩阵_去除全零行` 工作表。

**注意：**
数量核对通过仅表示数量归集关系满足程序检查，不代表业务映射完整或方量分摊合理。存在未映射业务时，应先审查异常明细。

## 5. 每日运输方量预处理：`pre_execute_V.py`

### 5.1 输入与输出

**输入：** `data/Record.xlsx`。 **输出：**
`output/Pre_V.xlsx`、`output/Pre_V_report.xlsx`。

必要字段：

| 字段       | 用途                   |
|:-----------|:-----------------------|
| `发运日期` | 确定方量归属日期       |
| `装载号`   | 运输记录识别及异常追溯 |
| `方量`     | 每条运输记录对应的方量 |

程序在每个可见工作表的前20行内自动查找必要表头；隐藏工作表跳过。可识别完整日期，也可在工作表名称包含年份时解析月日格式。合计、小计等汇总行不作为发运记录处理。

### 5.2 清洗与汇总规则

1.  除 `序号`
    字段外，对整行字段及原始列位置进行比较，完全重复的记录仅保留首次出现的记录。
2.  发运日期或方量为空的记录剔除，并写入异常明细。
3.  方量必须为非负有限数值；零方量记录不参与每日汇总。
4.  非空但无法解析的日期或非法方量会导致本次预处理失败，不发布本次新结果。
5.  按发运日期汇总同一天的有效运输方量。
6.  日期升序输出，不补充没有运输记录的自然日。
7.  使用十进制数值进行方量累计，输出时写入 Excel 数值。

### 5.3 输出文件

| 文件                             | 内容                                                                     |
|:---------------------------------|:-------------------------------------------------------------------------|
| `Pre_V.xlsx`                     | `Sheet1`，包含 `日期`、`方量` 两列，按日期升序排列                       |
| `Pre_V_report.xlsx` → `异常明细` | 记录剔除原因、来源工作表、原始行号及原始字段                             |
| `Pre_V_report.xlsx` → `处理统计` | 工作表数量、读取记录数、重复删除数、空值剔除数、零方量删除数及汇总数量等 |

重复与缺失可能同时命中，报告记录数不应简单理解为各类统计数字相加。

### 5.4 命令行参数

默认读取和输出路径分别为
`data/Record.xlsx`、`output/Pre_V.xlsx`，可通过参数指定其他路径：

``` bash
python pre_execute_V.py
python pre_execute_V.py --input "data/Record.xlsx" --output "output/Pre_V.xlsx"
python pre_execute_V.py --input "data/Record.xlsx" --output "output/Pre_V.xlsx" --report "output/Pre_V_report.xlsx"
```

含公式的输入工作簿按 Excel 缓存值读取，运行前应先在 Excel/WPS
中完成公式计算并保存。脚本不修改源文件。

## 6. 矩阵合并：`merge.py`

### 6.1 输入与输出

**输入：**

- `output/A_temp_result.xlsx`，读取 `矩阵_去除全零行` 工作表。
- `output/Pre_V.xlsx`，读取包含 `日期`、`方量` 表头的工作表。

**输出：**

- `output/A_result.xlsx`
- `output/A_logic.xlsx`（存在逻辑删除或比例重复记录时生成）
- `output/A_error.xlsx`（存在异常记录时生成）

### 6.2 日期匹配规则

程序分别读取模块数量矩阵末列日期及每日方量表日期，统一解析为自然日后进行匹配。

- 日期匹配采用一对一关系。
- 每个矩阵日期必须对应唯一一条有效方量记录。
- 同一天存在多条方量记录时，不自动累加、不取首条，整组记录转人工复核。
- 矩阵日期没有对应方量，或对应方量无效、日期重复时，该矩阵行不进入最终结果。
- 方量日期没有对应矩阵日期时，记录为方量未匹配矩阵。

### 6.3 矩阵处理规则

匹配成功后，将每日方量填入模块数量矩阵末列：

``` text
x1模块数量 | x2模块数量 | ... | xm模块数量 | 每日方量（m³）
```

随后执行以下检查：

1.  检查模块数量及方量是否为非负有限数值；空值、文本、公式、布尔值及负数均不作为有效数值。
2.  模块数量全部为零的记录进行逻辑剔除。
3.  仅一个模块数量非零，且该数量严格小于 `SINGLE_MODULE_THRESHOLD = 10`
    的记录进行逻辑剔除。
4.  对剩余记录，使用全部模块数量列及末列方量生成精确比例指纹。
5.  若两行全部对应数值成正比例，仅保留首次出现的记录，不对保留行进行缩放或平均。

比例重复判断采用十进制精确比例计算，不使用浮点近似容差，也不会省略任一非零列。

### 6.4 输出结构

| 文件            | 工作表         | 内容                                                                       |
|:----------------|:---------------|:---------------------------------------------------------------------------|
| `A_result.xlsx` | `汇总矩阵`     | 最终求解矩阵，无表头、无日期列；前面各列为模块数量，最后一列为每日方量     |
| `A_logic.xlsx`  | `逻辑删除`     | 全零模块数量及单模块低数量记录                                             |
| `A_logic.xlsx`  | `重复删除对照` | 比例重复记录，按组展示保留行与删除行                                       |
| `A_error.xlsx`  | 按异常类别生成 | 方量数据异常、方量日期重复、矩阵数据异常、矩阵未匹配方量及方量未匹配矩阵等 |

无逻辑删除或比例重复记录时，不生成空的
`A_logic.xlsx`；无异常时，不生成空的
`A_error.xlsx`，并清理对应同名旧报告（如存在）。

### 6.5 命令行参数

默认使用脚本目录下的 `output/`
文件夹，也可以指定输入及输出文件所在目录：

``` bash
python merge.py
python merge.py --output-dir "output"
```

**重要限制：**
各日期的模块列必须使用同一套模块定义和相同列顺序。列数一致并不能证明不同期间的
`x1…xm` 含义一致。比例去重会减少样本数，需保留删除对照报告以便复核。

## 7. 参数求解：`execute.py`

### 7.1 输入与结果结构

**输入：**

- `data/Resource.xlsx` → `模块信息` 工作表。
- `output/A_result.xlsx` → 第一张工作表 `汇总矩阵`。

`Resource.xlsx` 的 `模块信息` 必须包含：

| 字段             | 要求                                                               |
|:-----------------|:-------------------------------------------------------------------|
| `备件模块`       | 模块名称，不允许为空或重复                                         |
| `自变量`         | 按模块顺序依次为 `x1`、`x2`……                                      |
| `值` 或 `确定值` | 两者必须且只能存在一个字段；已填写值作为固定单位方量，空白表示待求 |

固定单位方量必须为有限正数，单位为 m³/件。

`A_result.xlsx` 第一张工作表必须命名为
`汇总矩阵`，数据无表头、无日期列，列数必须等于模块数加一。前面各列为模块数量，最后一列为每日总方量（m³）；所有数值必须为非负有限数值。

### 7.2 求解模型与固定值

模型形式为：

\[ \]

其中，() 为每日模块数量矩阵，() 为待估计模块单位方量，()
为每日总运输方量。

已填写的固定单位方量先参与每日固定方量计算，再从每日总方量中扣除，剩余部分用于待求模块估计。固定值不参与未知参数求解，结果中按原值保留。

程序通过矩阵数值秩、零空间及模块覆盖情况检查参数可识别性。无法独立确定的模块，即使数值优化得到候选值，也会标记为待复核估计，不应直接视为已确认结果。

### 7.3 可选求解模式

修改脚本顶部的 `MODE` 选择模式。当前代码配置为
`MODE = '3.1'`，脚本不会根据求解结果自动切换模式。

| 模式  | 方法           | 主要处理方式                                                                   |
|:------|:---------------|:-------------------------------------------------------------------------------|
| `1.1` | 严格方程       | 使用线性规划检查非负可行性及严格正性，并验证原始方量等式                       |
| `1.2` | 非负最小二乘   | 在非负约束下最小化预测方量与实际方量的残差平方和                               |
| `1.3` | 相对误差加权   | 根据每日原始总方量进行尺度加权，降低不同方量量级的影响                         |
| `1.4` | Huber稳健拟合  | 使用Huber损失降低较大残差的影响，不自动删除异常样本                            |
| `1.5` | 正则化最小二乘 | 在原始单位方量上引入L2惩罚，控制参数规模                                       |
| `2.1` | 对数参数MAP    | 在单位方量对数空间结合正态先验进行估计，不是完整贝叶斯后验推断                 |
| `2.2` | Bootstrap集成  | 通过重复抽样评估模块参数稳定性，统计有效抽样次数及经验区间                     |
| `3.1` | 正权重线性网络 | 通过正权重线性网络估计单位方量，使用验证集早停选择训练轮数，再使用全部数据重训 |
| `3.2` | 非线性神经网络 | 用于非线性总方量预测对照，不输出固定的模块单位方量                             |

### 7.5 结果验收与识别规则

未知模块的候选结果需要满足：

1.  求解器状态通过。
2.  单位方量为有限正数。
3.  满足 `MIN_RESULT_M3`
    配置的验收下限；等于下限可通过，小于下限不通过。
4.  满足对应模式的模块有效性要求；Bootstrap模式还需满足有效抽样次数要求。
5.  结合矩阵秩和零空间诊断判断模块是否可以独立确定。

`MIN_RESULT_M3`
仅用于结果验收，不是优化下限，不会把低于阈值的候选值强行抬高；固定正数不受该未知参数阈值筛选。

程序区分以下结果：

- **固定值：** 来自 `Resource.xlsx`，按原值保留。
- **可独立确定：** 通过数值检查且未被标记为无法独立确定，仍需业务核实。
- **估计值待复核：**
  有候选数值，但模块无法独立确定，不应直接作为正式标准。
- **未通过：** 求解器或模块验收条件未满足。
- **无业务样本：** 使用 `*` 标记。
- **模式3.2：** 仅提供非线性预测，不适用固定单位方量输出。

| `execute_explain.xlsx` | `样本拟合`         | 每日实际方量、固定方量、候选预测方量、误差及验证结果            |

### 7.7 误差指标与验证限制

解释报告记录RMSE、MAE、平均偏差、最大绝对误差、MAPE及R²等指标，并分别展示全量候选预测、输出数值试算及留出候选预测情况。

需要注意：

- 全量候选误差可能包含未通过模块的候选参数，不能直接视为正式输出结果的误差。
- 输出数值试算仅在相关模块均有已接受数值且任务求解通过时计算。
- 留出验证采用随机留出，不是按日期顺序进行的未来时间验证。
- 神经网络模式使用验证集选择训练轮数，因此该验证集指标不能视为独立测试集结果。
- 当全部样本总方量相同时，常数预测可能获得很低甚至为零的误差，不能据此证明单位方量识别准确。
- 正则化、先验约束及较高模块通过率均不能替代独立实测数据。

|  `0`   | 当前任务完成；模式3.2预测任务通过时也可返回0 |

## 8. 标准运行步骤

### 8.1 准备基础数据

1.  确认 `data/Resource.xlsx` 中 `备件信息` 的SKU与模块映射准确。
2.  确认 `模块信息` 中模块名称及 `x1…xm` 顺序连续、唯一。
3.  对未分类模块，可按需运行 `model.py` 生成匹配建议；人工复核后再维护
    `Resource.xlsx`。
4.  如需提前整理件号主数据，应在源数据准备环节完成清洗；本项目当前五个脚本中不包含独立的
    `clean.py`。

### 8.2 生成模块数量矩阵

将月度业务文件放入 `data/execute/`，文件命名为 `YYYY.MM.xlsx`，例如：

``` text
data/
└── execute/
    ├── 2026.08.xlsx
    ├── 2026.09.xlsx
    └── 2026.10.xlsx
```

执行：

``` bash
python pre_execute.py
```

检查 `output/A_temp_result.xlsx` 和
`output/A_temp_erro.xlsx`。重点核对SKU未匹配、模块映射异常、重复记录、非汽运剔除及数量平衡情况。

### 8.3 生成每日运输方量

将运输记录文件放入 `data/Record.xlsx`，执行：

``` bash
python pre_execute_V.py
```

检查 `output/Pre_V.xlsx` 和
`output/Pre_V_report.xlsx`，重点核对重复记录、缺失日期、缺失方量、零方量剔除及每日汇总结果。

### 8.4 合并每日数量与方量

确认模块数量矩阵与方量汇总的日期范围、业务范围及统计口径一致后执行：

``` bash
python merge.py
```

检查 `output/A_result.xlsx`，并按需复核
`A_logic.xlsx`、`A_error.xlsx`。确认最终矩阵每行的模块数量与末列方量对应同一天。

### 8.5 执行单位方量求解

根据需要修改 `execute.py` 顶部的 `MODE` 和相关参数，确认 `Resource.xlsx`
固定单位方量配置后执行：

``` bash
python execute.py
```

检查 `output/execute_result.xlsx` 和
`output/execute_explain.xlsx`。重点关注求解器状态、模块可识别性、待复核估计、验收下限、样本拟合误差及方量口径提示。

### 8.6 完整运行顺序

``` bash
python model.py                 # 可选：模块辅助匹配
python pre_execute.py           # 生成模块每日数量矩阵
python pre_execute_V.py         # 生成每日运输方量
python merge.py                 # 按日期合并并检查矩阵
python execute.py               # 求解模块单位方量
```

`model.py` 为辅助匹配环节，不是每次计算的必需步骤。`pre_execute.py` 与
`pre_execute_V.py` 相互独立，可分别执行，但必须在 `merge.py`
运行前完成并核对各自输出。

运行前建议关闭 Excel/WPS
中已打开的同名输出文件，避免文件占用导致发布失败。任何步骤失败后，都应先查看本步骤的错误信息，不应直接将目录中遗留的旧结果当作本次运行结果。

## 9. 应用边界与版本管理

### 9.1 统计口径与数据边界

- **模块数量口径：** `pre_execute.py`
  仅统计发运方式为”汽运”的收货记录，按箱号日期及模块归集；非汽运、重复及映射异常记录不进入正常矩阵。
- **运输方量口径：** `pre_execute_V.py`
  按发运日期汇总运输记录方量。应确认该方量与模块收货数量属于同一业务范围、同一统计日期口径。
- **日期匹配：** `merge.py`
  以自然日进行一对一匹配。日期不一致、重复日期或统计范围不同会导致矩阵行无法匹配或形成错误关联。
- **比例去重：** `merge.py`
  对模块数量及总方量整体成正比例的记录仅保留首次出现行。该处理会减少样本约束，需结合删除对照审查。
- **线性模型假设：**
  模型假设同一模块单位方量相对稳定，模块数量与总方量近似线性叠加；实际运输方量还可能受到包装方式、装载组合、车型空间利用、空隙及混装等因素影响。
- **可识别性：**
  样本天数多于模块数不代表所有模块都能独立求解。模块长期共同出现或缺乏独立数量变化时，可能无法分别确定单位方量。
- **实测校准：**
  求解结果应结合典型件实测尺寸、包装状态、料架或容器占用体积及独立样本进行校验，不宜仅凭拟合误差或通过模块数量确认准确性。

### 9.2 结果解释边界

单位方量是统计模型在当前业务口径下估计的模块平均参数。它不直接表示每个SKU的真实外形体积，也不自动等于包装后的运输占用体积。

若不同SKU在同一模块内存在明显尺寸、包装或装载方式差异，模块平均单位方量可能掩盖内部差异。对于无法独立确定的模块，应补充独立样本、固定实测值或优化模块分类后再进行复算。

### 9.3 版本与文件管理

建议每轮测算同时归档：

- 原始业务数据及运输记录版本；
- `Resource.xlsx` 主数据版本；
- 五个脚本的代码版本及求解配置；
- `A_temp_result.xlsx`、`Pre_V.xlsx`、`A_result.xlsx`；
- `A_logic.xlsx`、`A_error.xlsx` 及各类预处理报告；
- `execute_result.xlsx`、`execute_explain.xlsx`。

`output/`
保留当前运行结果，历史结果应按日期或批次另行归档。求解解释报告包含输入文件SHA256摘要及本次配置，可用于核对输入版本和追溯计算过程。

**最终应用原则：**
模型结果用于模块方量估计、业务分析及方案试算；正式标准值应经过数据口径审核、独立测量和业务确认后再纳入主数据。
